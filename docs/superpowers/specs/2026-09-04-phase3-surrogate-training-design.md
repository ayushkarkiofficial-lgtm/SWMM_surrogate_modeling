# Phase 3 Design — Surrogate Model Training

**Date:** 2026-09-04
**Project:** SWMM surrogate modeling (see `PROJECT_BRIEF.md`)
**Phase goal:** Train ML surrogates on the SWMM dataset to predict flood-relevant outputs,
compare Random Forest vs XGBoost, and validate accuracy + speedup (Brief §17–19, §23).

## 1. Prerequisite

Scale the training set to **500 runs**: set `N_RUNS = 500` in the Phase 2 pipeline and
regenerate `data/dataset.csv`. (100 runs took 3.7 s, so 500 ≈ 20 s.) Brief §14/§23 target
for a credible surrogate.

## 2. Data & targets

- Load `data/dataset.csv`, keep `status == "ok"`.
- **Features (X):** `rain_mult, imperv_mult, surf_n, infil_min, pipe_n`.
- **Three learning tasks:**
  1. `peak_discharge_cfs` — **regression**.
  2. *floods?* = `total_flood_vol > 0` — **binary classification** (flood stage 1).
  3. `total_flood_vol` on the **flooded subset only** — **regression** (flood stage 2).
- Zero-inflation of flood volume (~69% zeros in pilot) is handled by the 2-stage split
  rather than one regressor forced to fit the spike at zero.

## 3. Validation protocol

- **80/20 train/test split**, fixed `SEED = 42`, **stratified on flood class** so both
  splits contain flooded cases (~155 flooded of 500).
- **5-fold cross-validation** for the regression R² (stabler than a single split at n=500).
- Flood-volume regressor: split within the flooded subset (~124 train / ~31 test).

## 4. Models

For each task, **RandomForest vs XGBoost** from sensible defaults (no heavy tuning this
phase):
- Regressors: `RandomForestRegressor(n_estimators=300)`, `XGBRegressor(n_estimators=400,
  learning_rate=0.05, max_depth=4, subsample=0.9)`.
- Classifiers: analogous RF / XGB classifiers.

## 5. Evaluation

- **Regression:** R², RMSE, MAE (test) + 5-fold CV R²; predicted-vs-SWMM scatter +
  residual plot for the best model.
- **Classification:** accuracy, precision, recall, F1, ROC-AUC, confusion matrix.
- **Extreme-case check** (Brief §18): regression metrics on the top-20% peak tail — average
  accuracy can hide extreme-event failure.
- **Runtime comparison** (Brief §19): time 10,000 surrogate predictions vs the SWMM
  equivalent (@ ~0.037 s/run measured in Phase 2); report speedup.
- **Feature importance:** permutation importance for the peak model — a preview of Phase 4
  sensitivity analysis.

## 6. Artifacts

- `notebooks/phase3_surrogate.ipynb` — generated by `scripts/build_phase3.py` (same
  nbformat builder pattern as Phase 2; re-run to regenerate).
- `models/` — best model per task via `joblib` (`peak_regressor.joblib`,
  `flood_classifier.joblib`, `flood_volume_regressor.joblib`). Gitignored (regenerable).
- `data/phase3_metrics.csv` — RF-vs-XGBoost comparison table (tracked; small).
- Plots rendered inline; notebook saved as a readable report.

## 7. Success criteria

- Peak-discharge surrogate reaches high test R² (target > 0.9 given the smooth physics).
- Flood classifier separates flood/no-flood well (ROC-AUC clearly > 0.5, sensible recall).
- Runtime comparison shows orders-of-magnitude speedup over SWMM.
- A clear best-model recommendation per task, recorded in the metrics table.

## 8. Out of scope (later)

- Monte Carlo (Phase 4), permutation/SHAP sensitivity deep-dive (Phase 4), and the
  **Applicability-Domain** extension (see `ad-aware-surrogate-direction` memory) — AD comes
  after this phase.
